The browser sessions do the work. Jev answers small questions about what happened: did the flow recover, did the release behave correctly, should this result be escalated?

The surrounding program runs the checks in parallel and reports failures. Jev is not the whole agent. It is a fast decision-maker inside the system.

## 02 — Build an action map

Imagine an agent controlling a browser or an operating system. The application already knows which actions are legal:

```text
click(button_12)
scroll_down
go_back
ask_for_help
stop
```

The agent does not need a paragraph. It needs the right action.

Jev receives the current state, a question and the available choices. It returns probabilities across that action map. The application chooses, asks for review or stops.

> Reliable agents may depend less on better prompts and more on better action maps.

## 03 — LLM input, classifier output

[System One](https://typesafe.ai/blog/introducing-system-one-models-and-jev) is TypeSafe's name for models built to run inside software. Jev is its first public model.

It accepts messy, ordinary text:

```text
state:    "I changed plans and my invoice doubled."
question: route_to
answers:  billing | technical | sales
```

It returns a value from the allowed set and a probability. The useful abstraction is simple:

> Give the model state and a fixed question. Get back a decision that code can use.

Matija Šošić puts it plainly in [his short explanation](https://x.com/MatijaSosic/status/2100190746389135772): Jev is classifier-like, accepts unstructured text, and does not require a separate training run for every use case.

| Traditional LLM | System One / Jev |
| --- | --- |
| Generates a string | Returns a typed decision |
| Samples token by token | Samples decisions in parallel |
| Needs parsing before code can act | Fits directly into workflow control |

This is not JSON mode. JSON mode constrains the shape of generated text. Jev gives up text generation and starts with a fixed decision contract.

## 04 — Intelligence cheap enough to disappear

TypeSafe reports 70 to 500 millisecond response times, $0.042 per million input tokens, and gains of 20 to 200 times in speed and 40 to 400 times in cost on its System One tasks.

Those are early, self-reported numbers. And this is not Luna-level general capability. The interesting claim is narrower: small-model-level intelligence on bounded decisions, at a price that makes it practical to call the model constantly.

That changes the architecture. Instead of one visible AI feature, software can contain hundreds of tiny decisions: route, score, retry, inspect, verify and escalate.

If intelligence becomes 100 times cheaper, we will not make the same number of decisions and pocket the savings. We will use intelligence where no model was economical before.

## 05 — Confidence becomes application logic

TypeSafe calls its training method RLCD: Reinforcement Learning for Calibrated Decisions. Every decision includes probabilities, so uncertainty becomes something the application can act on.

| Refund probability | Application response |
| ---: | --- |
| 0.96 | Execute automatically |
| 0.67 | Request approval |
| 0.31 | Reject |

“Human in the loop” stops being a safety slogan. It becomes a threshold in code.

But TypeSafe's “can't hallucinate” language goes too far. Jev cannot invent an invalid output type. It can still choose the wrong valid answer. Type safety guarantees the shape, not the truth.

## 06 — The nervous system around the agent

Use a general model for goals, planning and unfamiliar work. Use Jev for the fast reflexes around it:

- Is this action permitted?
- Did the page change as expected?
- Should the agent retry?
- Is the result suspicious?
- Does a human need to see this?

Then let deterministic code execute, enforce permissions and keep the audit trail.

The first generation of AI software put one general model in the middle of everything. The next may use a general model only where the problem is genuinely general.

[TypeSafe raised a $40 million seed round led by DCVC](https://www.dcvc.com/news-insights/typesafe-emerges-from-stealth-with-a-new-way-of-doing-ai/). The money is a bet that software will need many small decisions more often than it needs another paragraph.

The most useful AI model may be the one that writes nothing.

## Coda

Software can use both kinds of model: one to plan, another to handle the thousands of decisions around the plan.
