## 01. The model knows the sentence, not the second

I wanted an agent to turn raw footage into short videos: a founder talking, some product shots, captions, music. The kind of edit a person does in Premiere in an afternoon.

The agent understood the brief. It read the transcript, found the best take, picked the line that should open the video. Then it had to express all of that as timestamps, and everything fell apart.

A cut is arithmetic. Word 12 starts at some offset in the source. The clip before it was trimmed, so everything after it shifts. A speed change stretches the rest. A title should appear on a specific word, which is now at a different place in the finished video than in the source. Every one of these is a subtraction or a multiplication the model has to carry in its head, and models are bad at carrying numbers.

Language models write code well and do arithmetic badly. Most AI video tools fight the second half of that sentence. I decided to lean on the first.

## 02. Let the file say what it means

[CutCraft](https://prefix-tree.github.io/cutcraft/) is a video editor as code. A video is one TSX file. The model writes it, and CutCraft resolves it, plays it in the browser and exports it.

The important part is how a cut is written:

```tsx
<Track id="main">
  <Clip id="hook" src="asset:founder" in="word:12" out="word:23.end" />
  <Transition id="x1" type="crossfade" duration={0.4} />
  <Clip id="broll" src="asset:product" in="shot:1" out="shot:1.end" fit="cover" />
</Track>
<Track id="overlays">
  <Title id="title" anchor="hook" at="word:14" duration={2.8}>Shed</Title>
</Track>
```

No line names a second of the finished video. The clip starts on the 12th word of the transcript and ends after the 23rd. The b-roll is the camera's second shot. The title hangs off the `hook` clip and appears on its 14th word.

`word:12`, `shot:1`, `silence:3`, `marker:intro`. These resolve against a manifest of the media: transcripts with word timings, shot boundaries, pauses. CutCraft does the math through every trim, speed ramp and transition. Trim the clip and the title stays on its word. A track plays its clips back to back, so nobody adds up start times.

This is how the model already reasons. It thinks "the sentence from word 12 to 23", not "8.43 to 14.07". The file now holds the thought instead of a lossy translation of it.

## 03. No tool catalog

The obvious design for an AI editor is a tool per action: `clip_trim`, `keyframe_add`, `transition_insert`. A hundred tools, a schema for each, and a model choosing among them one call at a time.

I did not build that. Models are measurably worse at choosing among many tools than at writing code. A catalog also has to be kept in sync with everything the editor can do, forever.

In CutCraft the model edits text. It reads the file, changes it and writes it back. A lint tells it what it got wrong, the way a compiler would: a missing asset, a cut inside a word, a title that leaves the safe zone or covers the captions, each reported at its line. The model can restructure a whole video in one edit, which no sequence of tool calls expresses well.

The editor still has actions. There are 119 of them, trim, move, retime, restyle, each with validation and undo. But they exist for a person's hands, not for the model.

## 04. A person and a model edit the same file

This is the part I care about most.

Every element in the timeline carries a literal `id`. When you drag the end of `hook` in the timeline, CutCraft finds that element and changes one token in the file. Not a project file beside it. Not a JSON blob the model never sees. The same TSX.

So the next reader, a person or a model, sees the edit as ordinary code. You can ask the agent for a rough cut, tighten two clips by hand, then ask the agent to add captions, and it reads your trims as if it had written them. There is no handoff, because there is nothing to hand off.

Most AI tools treat the human as someone who approves or rejects the output. I think the better shape is a shared document with two kinds of editors. Code already works that way. Video should too.

## 05. Free code where the timeline stops

The timeline is strict on purpose: compositions, tracks, clips, transitions, captions, keyframes. A fixed vocabulary is what lets an editor, a lint and a model find the thing a change belongs to.

Pictures are not strict. A `<Layer>` takes any React component, with CSS, canvas, WebGL, three.js or Motion, and runs it on the video's clock. Scrub backwards or play at 2× and a three.js scene shows exactly the frame for that time. The layer is still a timeline element, so it can be trimmed, moved and anchored to a word like everything else.

The player decodes with WebCodecs and seeks frame-exact. The export runs that same player in headless Chrome and captures each frame, so what you preview is what you get. An earlier version drew the export in Node. I removed it so there is one way to draw a frame.

## 06. Free, with no asterisk

CutCraft is MIT. No paid tier, no licence key, no watermark on the frames.

The projects closest to it ask for something. Remotion has a paid company licence. Diffusion Studio stamps a watermark on every frame without a licence key. A player, an editor that writes back to the file, a frame-exact export and a layout check are infrastructure for anything built on video. Building on either would carry those terms into everything made with it. So CutCraft is written from scratch, on open libraries: React, zod, three.js, Motion and Mediabunny.

## 07. Try it with your agent

CutCraft ships as an Agent Skill. In Claude Code:

```text
/plugin marketplace add prefix-tree/cutcraft
/plugin install cutcraft@prefix-tree
```

Then put your footage in a folder, with a Whisper transcript beside each recording, and brief the agent the way you would brief an editor:

> Make a 30 second vertical clip from talk.mp4 for Reels. Open on the sentence about shipping on Fridays, keep only the best take of each line, add karaoke captions and a lower third with my name.

The agent adds the media, writes the file, checks the layout, renders stills of each cut to look at, fixes what it sees and exports the video. Without footage, a first video is a dozen lines and `npx cutcraft hello.tsx --out hello.mp4`.

It is version 0.3. The export is slow on a server without a GPU, because WebGL runs in software there. Handing a clip's frames to free code is next, and so is an open editor package with the timeline and inspector. The [docs](https://prefix-tree.github.io/cutcraft/), [examples](https://prefix-tree.github.io/cutcraft/examples) and [source](https://github.com/prefix-tree/cutcraft) are all public.

## Coda

The lesson is not about video. When a model fails at a task, check what you are asking it to express. Often it understands the problem and fails at the encoding. Change the encoding to match how it reasons, put the arithmetic in software, and keep the result in a format a person can edit too.
